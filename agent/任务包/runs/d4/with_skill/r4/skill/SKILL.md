# 先挖约束，再校逻辑，最后动手

做「按规范判数据」这类活，直接上手判基本都会返工。我的做法是三轮：第一轮只读文档挖约束，第二轮只看示例校逻辑，第三轮才真正动手填。三轮的产出分别是约束清单、判定顺序、成品表。

## When to use

- 手里有一份参考文档（规范、标准、操作规程），任务是按它对数据表逐条给出判定；
- 文档之外还附有示例——案例说明、判断样例、填好的样表都算；
- 交付有硬性格式要求：结论从给定枚举里选、填在指定文件里、输入不许改。

三类情况用不上这套：没有参考文档的自由分析；纯计算、无判定成分的任务；示例本身就是答案、照抄即可的填空。

## How to use

**第一轮：通读文档，把硬约束挖干净，一条不漏。**

硬约束藏在几种句式里，逐类找：

- **枚举与格式**：「只能」「不得」「必须使用」开头的句子——这是结论的值域，抄下来贴在手边；
- **触发条件**：「满足……的，判为……」——每条记下条件到结论的映射，连条款号一起抄；
- **回退与缺省**：「……为空时，按……执行」——这类规则最爱藏在主句的从句、括号或末尾补充里，读快了必漏。它决定关键列缺数据时怎么办，漏了它，空值行只能瞎猜；
- **排除与优先**：「……的，不纳入本次判定」「无论……均……」——注意这些措辞，它们改变判定的适用范围和先后。

挖完自检一条：文档里还有没有哪句话，没被抄进清单？有就回去重读。清单没建全，后面全白干。

**第二轮：把示例当测试用例，反推判定顺序。**

示例不是给你抄格式用的，出题人挑每条示例都有目的。两个动作：

一是**给每条示例找它演示的约束**。哪条约束在示例里找不到对应，多半不是示例漏了，是你没读懂示例想教的东西，回头再读。特别留意那些「别扭」的示例——数值明明超标却判没事、指标明明正常却要处理的，这类示例演示的就是优先级和排除规则。

二是**用示例反推判定顺序**。一行数据可能同时命中多条约束，判哪个取决于顺序。顺序不用凭感觉排：找示例里互相冲突的行，看它的最终结论站在哪条约束一边，哪条就该排前面。排完把全部示例逐行代进去验证——任何一条示例的结论对不上，就是顺序排错了或者约束挖漏了，改清单和顺序，不是改示例。

**第三轮：按清单和顺序动手，一次成型。**

- 每行数据把整张清单过完再下结论，不要命中第一条就停；
- 结论只从第一轮抄下的值域里选。想写值域外的词（「数据不足」「待确认」）时，停一下——这说明有缺省规则没挖到，回第一轮；
- 依据栏把推理链写全：用了哪条、取了哪个值、这个值是记录给的还是回退规则推的。同一列有两个候选值时要说明取舍；
- 填在任务指定的现成文件里，不动输入；
- 交之前对着示例和清单复查一遍：结论列和依据栏说的是不是同一件事，每行是否都被说明文档覆盖。

## 什么时候回头重来

三个信号，出现任何一个就回上一轮：

- 某行的结论落在值域外 → 回第一轮，缺省规则没挖全；
- 某行同时命中多条约束、拿不准判哪个 → 回第二轮，顺序没被示例验证过；
- 依据栏和结论列对不上 → 第三轮誊写时手误，对着推理链改结论，别反着来。
