# 机房设备检修判定说明

- 依据文件：《机房设备维护规范 v3.2（现行）》第 4 章「停机检修判据」
- 数据来源：《巡检数据.csv》（本次共 9 台设备）
- 判定日期：2026-09-29
- 结论取值域：**需检修 / 无需检修 / 不适用**

---

## 一、判定规则与优先级

### 1. 条款清单（第一轮挖出的硬约束）

| 条款 | 触发条件 | 结论 |
| --- | --- | --- |
| 4.1 | 运行温度 **超过** 额定温度上限 | 需检修 |
| 4.1 回退规则 | **额定温度上限列为空** 时，改按机柜级限值：通用计算机柜 **62 ℃**、高密度 GPU 机柜 **80 ℃** | 同上，据此判断是否超限 |
| 4.2 | 24 小时内告警 **≥3 次** | 需检修，**无论温度是否超限** |
| 4.3 | 状态为「厂商保修返修中」 | 不纳入本次判定，判为 **不适用** |

### 2. 判定顺序（第二轮校准结果）

工作区未附填好的样表或判定示例，因此顺序以规范自身措辞校验，结论如下：

1. **先看 4.3 排除**：状态为「厂商保修返修中」的设备直接判「不适用」，不再进入 4.1/4.2 判定。
2. **再合并 4.1 与 4.2**：二者是**并集**关系，命中任意一条即「需检修」。4.2 明确「无论温度是否超限」，因此告警达标时，即使温度正常也判需检修。
3. **两条都未命中**才判「无需检修」。

### 3. 两个易错点

- **「超过」是严格大于，等于不算超过**：运行温度 = 额定上限时不触发 4.1。
- **空旷值要走回退规则**：额定温度上限为空并非「数据不足」，规范已规定按机柜级限值执行，不得因此搁置判定。

## 二、逐台判定

### SV-501 —— 需检修（触发 4.2）
- 额定温度上限列为空 → 按回退规则取通用计算机柜限值 **62 ℃**；运行温度 60 ℃，未超过上限，4.1 不触发。
- 24h 告警 **3 次 ≥ 3 次** → 触发 4.2，无论温度是否超限，判**需检修**。
- 该行演示 4.2 的独立触发：温度正常但告警达标，照样检修。

### SV-502 —— 无需检修
- 回退取通用计算机柜限值 62 ℃，运行温度 60 ℃，未超限，4.1 不触发。
- 24h 告警 0 次 < 3，4.2 不触发。
- 两条均未命中，判**无需检修**。

### SV-503 —— 需检修（同时触发 4.1、4.2）
- 运行温度 75 ℃ **＞** 额定上限 70 ℃ → 触发 4.1。
- 24h 告警 3 次 **≥** 3 → 同时触发 4.2。
- 两条均指向需检修，判**需检修**；触发条款栏两条并列。

### SV-504 —— 需检修（触发 4.1）
- 运行温度 75 ℃ **＞** 额定上限 70 ℃ → 触发 4.1，判**需检修**。
- 24h 告警 2 次 < 3，4.2 不触发（与 SV-503 同温、仅告警数不同，用于区分两条规则）。

### SV-505 —— 无需检修
- 运行温度 85 ℃ **≤** 额定上限 88 ℃，4.1 不触发。
- 24h 告警 0 次 < 3，4.2 不触发。
- 判**无需检修**。

### SV-506 —— 不适用（触发 4.3，排除优先）
- 运行温度 95 ℃ **＞** 额定上限 88 ℃，单看 4.1 本应判检修；但**状态为「厂商保修返修中」**。
- 依 4.3「不纳入本次判定」，4.3 优先于 4.1，判**不适用**。
- 该行是优先级示例：温度超标仍不判检修，说明 4.3 排在温度判断之前。

### SV-507 —— 需检修（同时触发 4.1、4.2）
- 额定温度上限列为空 → 按回退规则取高密度 GPU 机柜限值 **80 ℃**；运行温度 81 ℃ **＞** 80 ℃ → 触发 4.1。
- 24h 告警 5 次 **≥** 3 → 同时触发 4.2。
- 判**需检修**。本行同时验证「高密度 GPU 走 80 ℃ 限值」这条回退分支。

### SV-508 —— 无需检修（边界值）
- 运行温度 66 ℃ **等于** 额定上限 66 ℃，规范用词为「超过」，严格大于才算超限，故 4.1 **不触发**。
- 24h 告警 0 次 < 3，4.2 不触发。
- 判**无需检修**。该行为边界示例：等于上限不判检修。

### SV-509 —— 需检修（触发 4.1）
- 运行温度 67 ℃ **＞** 额定上限 66 ℃ → 触发 4.1，判**需检修**。
- 24h 告警 0 次 < 3，4.2 不触发（与 SV-508 仅差 1 ℃，用于区分「超过」与「等于」）。
