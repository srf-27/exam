## 补充内容
### 任务理解
难点在三条判据**只能填一个**,所以应该有优先级，而不是并列全部判断一遍
```text
判据
4.1　运行温度超过**额定温度上限**的，判为需检修。
　　 额定温度上限见巡检数据表对应行；**该列为空的设备，按其机柜级限值执行**。
　　 机柜级限值：通用计算机柜 62 ℃，高密度 GPU 机柜 80 ℃。
4.2　24 小时内告警 **≥3 次**的，无论温度是否超限，均判为需检修。
4.3　状态为「厂商保修返修中」的设备不纳入本次判定，判为「不适用」。

```
```text
判断案例与说明
SV-001（题眼） 额定上限列为空。按 4.1 末句应改用机柜级限值 62 ℃，实测 64 ℃ 超限。
只看额定上限那一列、见空就跳过，会漏判。
SV-002 告警 4 次触发 4.2。温度 66 ℃ 未超 68 ℃——不能因为温度没超就判无需检修，
4.2 写明「无论温度是否超限」。
SV-003（干扰项） 温度 71 ℃ 已超 68 ℃，看起来该检修，但状态是返修中，按 4.3 判不适用。
SV-004 额定上限 75 ℃ 已列出，实测 78 ℃ 超限。不能因为它在 80 ℃ 的 GPU 机柜里就放过——
机柜级限值只在额定上限**空缺时**启用。
```
结合上面的判据和案例，我们可以大体总结出判断流程：
```text
对于一行数据：
1.查「状态」：如果状态是「厂商保修返修中」，「判定」判为「不适用」，「触发条款」记作「4.3」，
「判断依据」记作「状态为厂商保修返修中，按4.3不纳入判定」，并退出判断；否则继续下一步判断。
2.查「24h告警次数」：如果次数>=3 次，「判定」判为「需检修」，「触发条款」记作「4.2」，
「判断依据」记作「24h告警次数>=3次」，并退出判断；否则继续下一步判断。
3.查「额定温度上限(℃)」：如果为空，那么继续查「机柜用途」，如果是「通用计算」，把这一行的「额定温度上限(℃)」
替换为「62」，如果是「高密度GPU」，把这一行的「额定温度上限(℃)」替换为「80」，然后进入下一步判断；否则继续下一步判断。
4.查「运行温度(℃)」和「额定温度上限(℃)」：如果「运行温度(℃)」>「额定温度上限(℃)」,「判定」判为「需维修」，「触发条款」记作「4.1」，
「判断依据」记作「运行温度超过预设/默认温度上限值」，并退出判断；如果「运行温度(℃)」<=「额定温度上限(℃)」,「判定」判为「无需维修」，「触发条款」不记，
「判断依据」记作「所有指标均正常」，并退出判断；
```
领域内的专业人士最可能卡在两处：一是"缺数据怎么办"——运维习惯上遇到空列要么跳过、要么写"数据不足/待确认"，而任务书只给了三个枚举值，
逼着你必须找到回退规则；二是"数值结论与状态条款冲突时谁优先"——设备确实在超限运行，规范却把返修中的设备整条排除在外。此外还有一层约束陷阱：
结论只能用三个枚举值。

#### 3.3 失分定位到行：全部集中在一个失败模式

逐行比对把 31 条失分**全部**定位到 4 个具体设备行（含边界行的 2 次 G4 失分）：

| 失败模式 | 出现次数 | 具体行 | 期望 vs 实际 |
|---|---|---|---|
| **M1 多条判据同时命中时，把命中的条款都列上（或挑了温度那条）** | **39 行次** | `d2/SV-204`、`d4/SV-401`、`d5/SV-503`、`d5/SV-507`（4 行 × 约 10 次运行） | 期望 `4.2`，实填 `4.1、4.2` / `4.1；4.2` / `4.1;4.2`（60 行次里 39 次）；`d4/SV-401` 有 1 次直接填 `4.1` |
| **M2 无需检修的行，也把「未触发的条款」写进条款列** | 11 行次 | `d1/SV-102`、`d1/SV-103`、`d2/SV-201`、`d2/SV-206`、`d2/SV-207` | 期望留空，实填 `4.1、4.2` / `4.1` / `4.1（未触发）` |
| **M3 边界行填了枚举外的值** | 2 行次 | `d2/SV-208`（额定空 + 机柜用途「存储专用」） | 判定列填 `待确认`，不在 `{需检修,无需检修,不适用}` 内 → G4 归零 |

M1 是**本题的核心难点，数据把它量化了**：4 个「温度超限 + 告警 ≥3 同时命中」的设备行，几乎每次运行都被判错条款。这正是两个难点——三条判据只能填一个、必须有优先级；模型能正确给出「需检修」这个结论（G5 两组 50/50 满分），却在「该记哪一条」上反复翻车（G6 只有 10/25、9/25 满分）。这也说明初始 4 行数据为什么不够用：它的四类分支各只有一行、且没有一行同时命中多条判据，这个失败模式根本没有触发机会。

#### 3.5 为什么 25 条 / 组（共 50 条）足够支撑结论

1. **5 组数据不是抽样，是定向覆盖**：四类规则分支（状态 / 告警 / 超限 / 正常）与两类边界（温度恰等于上限、机柜用途未知）都落到了具体行上，38 个可判行/组——不是「碰运气碰到几种情况」，而是把规则空间铺满。
2. **每组 5 次重复用来消解单次采样噪声**：同一组数据同一组的 5 条分数并不完全相同（如 `d2/no_skill` 落在 73.9–85.7），说明重复有必要；5 次足以看出「失分是稳定的还是偶发」——结果显示 M1 在 4 个行上是**每次必犯**，不是偶发。
3. **失分高度集中，说明主失败模式已被充分暴露**：50 条里 31 条失分，全部落在 3 条判分点、4 个具体设备行上。若是样本量不足（没铺到关键情况），失分会是零散、随机的；现在是同一个模式反复出现，追加条数只会重复同一结论。
4. **Gap 的精度已经够用**：均值差 0.21，95% 置信区间约 [−1.5, +1.9] 分。也就是说本数据能排除「Skill 带来 ≥2 分增益」这类结论；再多跑条数只会收窄这个区间，不会把「无显著差异」变成「有显著差异」。

### 四、Skill

`skill/SKILL.md`（`name: constraint-mining-from-docs`）：定位为**增量**——无此 Skill 任务亦可完成，仅难度更高。

任务所需的全部信息（规范条文、空表、枚举值）都在材料里，模型直接读材料即可完成；no_skill 组 25 条中 10 条满分，实证「无 Skill 亦能完成」。
此 Skill 提供的是一套通用流程——第一轮从参考文档挖硬约束（枚举与格式 / 触发条件 / 回退与缺省 / 排除与优先四类句式），第二轮把示例当测试用例反推判定顺序（「别扭的示例演示的就是优先级」），第三轮才动手填表并自检。它降低的是「漏读回退规则」「优先级排错」这类过程风险，不提供本题的任何结论，也没有调用判分器的检测，所以这样效果其实也较差。

**泄漏说明：无。** Skill 全文不含任何具体数值、名称、阈值——已程序化自检：全文**无任何阿拉伯数字**，也不含温度限值、告警次数、条款号（4.1/4.2/4.3）、设备编号（SV-xxx）、机柜用途（通用计算 / 高密度GPU）、状态值（厂商保修返修中）等本题关键词。最接近的表述是「回退规则常藏在主句从句、括号或末尾补充里」「数值超标却判没事的示例演示的是优先级」这类对文档写作与出题方式的一般性描述，不泄漏本题任何答案。

**Skill 的 Gap：**

- **两组各自得分**：no_skill 程序化 85.49 / 88 + 语义 11.84 / 12 = **97.33**（n=25）；with_skill 程序化 85.53 / 88 + 语义 12.00 / 12 = **97.53**（n=25）。
- **差距数值**：**+0.21 分**（with_skill 略高）；置换检验（20 000 次重排，25 vs 25）双侧 **p = 0.81**，不显著；按数据分，5 组里 d1 为 −1.07、d2 +0.63、d3 0.00、d4 +1.20、d5 +0.27，方向不一致。
- **差异出现在哪几条判分点**：14 条判分点里只有 3 条出现差异——G4（+0.40，满分率 23/25 → 25/25）、G6（−0.49，10/25 → 9/25）、G7（+0.13，23/25 → 25/25）；G1、G2、G3、G5、G8、G9、G10 七条两组均 25/25，无任何差异。
- **对该差距的判断**：存在两个**方向相反**的小效应，净效应约等于零。正向的是 G4/G7：no_skill 的 2 次 G4 失分**全部**来自边界行写了枚举外的「待确认」，而 Skill 第三轮明确写了「想写值域外的词时，停一下——这说明有缺省规则没挖到，回第一轮」，正对着这个行为；with_skill 组 25 条无一次写出枚举外的值。负向的是 G6：Skill 第二轮「每行数据把整张清单过完再下结论，不要命中第一条就停」这句，容易被理解成「把命中的条款都列出来」，与本题「命中即退出、条款列只记一条」冲突——`d1/with_skill/r3` 就是典型：它在两行无需检修的格子填了 `4.1、4.2`（本意是「两条都没触发」），这批失分在 no_skill 里没有出现。

因此判断是：**Skill 有效，但被它自身一句有歧义的表述抵消了**；第二轮那句改成「全清单只用来决定结论，条款列只记最先命中的那一条」，很可能把 G6 的 −0.49 转为正增益。但是这样子改又不一定会通用了，也许有些场景是需要多个理由的
- 另需说明**天花板效应**：两组均值都已 > 97、程序化 G5 是 50/50 满分，本任务对 `deepseek-chat` 仍然偏易/或者说判分器可能没有考虑到更多情况，Skill 的增益空间较小。

### 五、A 问：哪几条最可能误判一个已做对的提交？

G4 曾把「需检修（告警触发）」判为非法枚举值（已加归一化）；
