# Rubric：机房设备停机检修判定


## 1. 判定规则

对 `巡检数据.csv` 的**每一行**，按下列顺序执行，命中即退出：

| 步 | 检查对象 | 条件 | 判定 | 触发条款 | 判定依据（类别） |
|---|---|---|---|---|---|
| 1 | 状态 | = `厂商保修返修中` | 不适用 | 4.3 | 状态排除：须体现「返修 / 保修 / 4.3」 |
| 2 | 24h告警次数 | ≥ 3 次 | 需检修 | 4.2 | 告警触发：须体现「告警」与阈值 3 |
| 3 | 额定温度上限(℃) | 为空 | *（不判定，先定值）* | — | 按机柜用途取机柜级限值：通用计算 → **62**；高密度GPU → **80** |
| 4 | 运行温度 vs 额定温度上限 | 运行 > 上限 | 需检修 | 4.1 | 温度超限：须体现「超 / > ＞ 高于」与「温度 / ℃」 |
| 5 | 运行温度 vs 额定温度上限 | 运行 ≤ 上限 | 无需检修 | *（不记）* | 指标正常：须体现「正常 / 未超」 |

规则补充（原规则未覆盖的边界，显式声明，见第 6 节）：第 3 步若机柜用途不是「通用计算 / 高密度GPU」
且额定上限为空，则限值无法确定，该行按**不适用**处理。

> ⚠️ 术语口径：任务书与 Gold 的结论枚举是 `需检修 / 无需检修 / 不适用`。
> 规则原文写作「需**维修** / 无需**维修**」，本 rubric 按**任务书枚举**实现（Verifier 中 `NEED/NO_NEED` 两个常量）。

## 2. 通用性：分数如何随行数缩放

行相关的三条（G5/G6/G7）总分固定，按数据行数 N 均摊到每一行，因此换数据后总分仍是 100：

| 项 | 总分 | 每行得分 |
|---|---|---|
| G5 判定正确 | 32 | 32 / N |
| G6 触发条款正确 | 16 | 16 / N |
| G7 判定依据类别正确 | 12 | 12 / N |

当前数据 N = 4，即每行 8 / 4 / 3 分（与 v1 单行权重一致）。

## 6. 边界与已知取舍

1. **规则未覆盖的边界**：额定上限为空且机柜用途不属于「通用计算 / 高密度GPU」时，规则没有给出限值。
   Verifier 按「不适用」处理并在输出中标注，该行不计入 G5/G6/G7 的分母。这是本 rubric 对规则的显式补充，不是 Gold 里有的东西。
2. **G7 不做整串精确比对**：规则给出的依据文本是模板（如「运行温度超过预设/默认温度上限值」），
   但 Gold 写得更详细（含具体数值）。按类别做包含性检查可以让两种写法都通过；
   代价是无法区分"写对了类别但数值写错"——这类错误由 G5/G6 与语义分共同兜底。
3. **分数随行数缩放**：N 变化时 G5/G6/G7 的每行分值随之变化，但三条总分（32/16/12）与总 100 分不变。
